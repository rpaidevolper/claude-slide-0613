# Day 3 講師教學與備課手冊（私人版，不發學員）

> 定位：`outline.md` 是課堂上照著跑的 run sheet；`handbook.md` 是學員的複製區；**這份是你自己的攻略**——備課期做什麼、前一晚檢查什麼、課堂上卡住怎麼救。

---

## 1. 課程一頁總覽

**一句話定位**：把 Day 2「資料自己回來」升級成「系統自己看資料、自己判斷、自己寄信、還給你一個後台」。

**教學法核心**：學員全程不寫 code。環節一讓他們「看得懂 code 讀了哪格、寄給了誰」，環節二起只做一件事——**把需求說清楚，讓 Gemini 寫**。你在台上示範的不是程式能力，是「說清楚需求」的能力。

**四主軸 × 11 動手速查**：

| 主軸 | 動手 | 產出 | 學員信箱收到什麼 |
|---|---|---|---|
| 一、第一次指揮雲端 | 1 Logger／2 寫入 A1／3 自我介紹 | 授權完成 | （信寄到**你的**信箱＝打卡） |
| 二、讓 AI 幫你寫 | 4 供給緊張提醒／5 沉睡客戶預警 | 兩支 Gemini 生的 GAS | 詢價提醒信＋沉睡清單（C002/C007） |
| 三、把 Gemini 裝進系統 | 6 API key／7 客製話術／8 AI 週報／9 觸發器 | GAS 內呼叫 Gemini | 客製話術信＋AI 週報 |
| 四、GAS 做出網頁 | 10 後台程式碼／11 部署 | 一個真的網址 | —（產出是網頁） |

**全天三個成功指標**（顧好這三個，其他都可以放）：
1. ⏱ 開場後 **40 分鐘內人人執行過第一行 code**（動手 1）。
2. 🎯 動手 5 **全班名單都是 C002＋C007**（劇情驗收點）。
3. 🌐 **人人部署成功、手機能開自己的後台網址**（全日最後高潮）。

## 2. 備課期任務（課前一週開始）

### 2.1 行情 Google Sheet 製作（優先級：🔴 最高）

1. 上傳 `範本_新創金屬_行情資料.xlsx` 到 Drive → 右鍵「用 Google 試算表開啟」→ 檔案 → 儲存為 Google 試算表。
2. **建議刪掉「挑戰_近30日走勢」分頁**——課程不用它，留著只會讓學員問「這是什麼」。若想留做課後挑戰素材，改名成「附錄_走勢(課後挑戰)」以免混淆。
3. 建「建立副本」連結：分享 → 知道連結者「檢視者」→ 複製連結 → 把網址結尾的 `/edit?...` 改成 `/copy`。自己開無痕視窗測一次。
4. 連結放兩個地方：handbook 頁首（貼 Notion 時補）＋課堂聊天室置頂。

> ⚠️ **關鍵風險：動手 4 的寄信條件是「F4 < 0 且 F3 > 0」**。範本數據（F3＝+69.31、F4＝−1300）條件成立，信一定寄得出來。**不要**手癢換成當日真實行情——哪天銅價跌了，全班執行後「今日無供給緊張訊號」，高潮直接消失。就用範本這份凍結的數據，開課前自己跑一次保底碼確認有寄信。

### 2.2 沉睡客戶門檻檢查（優先級：🔴 最高）

動手 5 用 `new Date()` 算沉睡天數，**答案會隨上課日期漂移**：
- 以檔案資料推算：C002 約 137 天、C007 約 100 天，下一個逼近門檻的是 C004（差不多 49 天）。
- 7/22 上課安全無虞；但**若課程延到八月底之後，C004 會跌過 90 天門檻**，名單變三個人。
- SOP：**課前一天自己跑一次動手 5 保底碼**，確認 Logger 裡只有 C002/C007 超過門檻。若多出人，把 `沉睡天數門檻` 調高（例如 120），並同步改 handbook 的骨架、參考解答 prompt 與保底碼三處。

### 2.3 測試標準 prompt（優先級：🟠 高）

用一個乾淨（無歷史對話）的 Gemini 帳號，**每個標準 prompt 各測三次**（動手 4、5 參考解答、7、8、10）：
- 確認三次產出都能貼上直接跑。跑不動的紀錄失敗模式（常見：用了 `openById` 要你填 ID、把信箱寫成 placeholder 卻沒放最上面、多包了一層 onOpen）。
- 把常見變形記在下面 §3 的排除 SOP 裡自己的補充欄。
- 測的時候順便截「Gemini 產出畫面」給簡報 Result 頁用。

### 2.4 部署示範專案（優先級：🟠 高）

自己完整走一次動手 10–11：貼 `Code.gs`＋`index.html` → 部署 → 開網址 → 新增一筆訂單 → 確認 Sheet 多一列。**保留這個專案當課堂備援**：若現場示範炸了，直接切到這個已部署好的網址繼續講。

### 2.6 講師備用 API key

- 用你自己的帳號多建一組 key，寫在只有你看得到的地方（不要進簡報、不要進手冊）。
- 用途：動手 6 卡關的學員先借用你的 key 跟上進度（口頭唸給他填指令碼屬性），課後回 AI Studio **刪除這組 key**。
- 提醒借用的學員：這組課後會失效，回家要自己申請。

## 3. 分段教學攻略

### 開場（30 min）

- **教學意圖**：不是暖場，是「換工具的合理性」——學員必須帶著「PAD 管本機、GAS 管雲端」的心智模型進環節一，不然會問「為什麼不繼續用 PAD」。
- **節奏**：頁 4 前情提要放行情 Excel 截圖時，指著它說「這就是上週大家做出來的東西」——有上過 Day 2 的人會立刻接上。頁 8 講完直接叫大家點連結建立副本，**確認人人開得了副本再進環節一**（這是第一個隱形卡點：有人沒登入 Google 帳號）。
- **卡點 SOP**：建立副本打不開 → 十之八九是公司帳號/個人帳號切換問題，讓他用無痕視窗登個人帳號重開。

### 環節一（75 min｜動手 1–3）

- **教學意圖**：不是教語法，是建立「執行 → 去哪看結果」的迴路＋闖過授權關。後面所有動手都靠這個迴路自救。
- **節奏**：動手 1 前投影你自己的編輯器，滑鼠移動放慢。授權頁（頁 17）是全天最需要「帶著點」的一頁——先預告「等下會跳一個看起來很可怕的畫面，那是正常的」，恐懼感先拆掉。
- **卡點 SOP**：
  - 找不到「進階」→ 授權視窗語言是英文（Advanced），或視窗被瀏覽器擋（看網址列的彈窗攔截圖示）。
  - 執行沒反應 → 沒選對函式就按執行（下拉選單選錯），或根本沒存檔。
  - 信沒收到 → 查垃圾郵件；GmailApp 用的是登入帳號，確認他 Apps Script 登的是要寄信的那個帳號。
- **時間管理**：0:30 開始，**1:10 前要完成動手 1**（成功指標一）。落後就啟動 ⚡：Troubleshoot 頁 30 秒帶過，卡關的人 Break1 個別救。

### 環節二（100 min｜動手 4–5）

- **教學意圖**：這 100 分鐘是整門課的靈魂。學員要帶走的不是那兩支程式，是「**資料在哪／條件是什麼／要做什麼**」這個三段式提問法。頁 23 逐句解構 prompt 時，每唸一段就問「這句在跟 AI 講三段裡的哪一段？」
- **節奏**：動手 4 你先示範完整一輪（貼 prompt → 看 Gemini 生 → 貼回 → 執行 → 開信箱），全程不要超過 5 分鐘，讓學員感受「這麼快」。然後才放他們自己做。動手 5 放手，你巡場。
- **卡點 SOP**（先在台上講明「AI 生的每個人都不一樣，是正常的」）：
  - Gemini 生的 code 用 `openById('請填ID')` → 最常見變形。兩條路：把 ID 貼進去，或直接貼保底碼。**課堂原則：卡超過 2 分鐘就貼保底碼，不現場 debug AI 的產出**。
  - 生出兩個以上函式或要求安裝東西 → 直接保底碼。
  - 執行成功但沒收到信 → 看 Logger：走到「今日無供給緊張訊號」代表他自己改壞了條件或讀錯分頁名（副本改過名）。
  - 忘了把信箱改成自己的 → 信寄去 placeholder，Logger 有寄出紀錄但收不到。
- **驗收**：動手 5 結束用 outline 的驗收台詞點名單（見 §4）。
- **時間管理**：動手 4 佔 25 分鐘、動手 5 佔 25 分鐘為上限。動手 5 若太多人骨架填不出來，直接投影參考解答 prompt 讓大家照貼——「自己填」是加分項不是必達項。

### 環節三（90 min｜動手 6–9）

- **教學意圖**：AI 角色三層堆疊——你去找 AI（環節二）→ 系統去找 AI（動手 7、8）→ 系統定時自己來（動手 9）。每過一層都口頭標記「注意，AI 的位置變了」。
- **節奏**：動手 6 是本環節最大摩擦點，預留 15 分鐘。投影你的畫面一步一步帶（登入 → 建 key → 複製 → 指令碼屬性）。動手 7 → 8 之間啟動 ⚡：API 概念不重講，直接說「同一招，換素材」。
- **卡點 SOP**：
  - key 貼在程式碼裡而不是指令碼屬性 → 能跑但要糾正（安全紅線），示範搬到屬性。
  - 屬性名稱打錯（GEMINI_APIKEY 少底線）→ Logger 會印「尚未設定 GEMINI_API_KEY」，對照檢查。
  - UrlFetchApp 回 400 → key 複製不完整（少字元）；403 → key 無效或被刪；429 → 免費層速率限制，全班同時打 API 可能踩到，等 30 秒重跑，或分批執行。
  - Gemini 回傳結構異常 → 保底碼會印原始回應，十之八九是 key 問題或安全過濾，換個措辭重跑。
  - 觸發器儲存時再跳一次授權 → 正常，照動手 3 流程。
- **時間管理**：落後 10 分鐘 → 動手 7 改成你示範、學員只看（他們手上有保底碼可回家跑），動手 8、9 必做（週報＋觸發器是課程標題承諾）。

### 環節四（50 min｜動手 10–11）

- **教學意圖**：給「成就感的實體」——一個網址。概念（doGet/HtmlService）點到為止，重心全在**人人部署成功**。
- **節奏**：動手 10 不執行、直接部署，先講明「這支不是按執行鍵跑的，是部署成網頁」——否則一定有人按執行然後問為什麼沒畫面。部署設定頁（頁 48）投影帶著點：執行身分「我」、存取權「只有我自己」。
- **卡點 SOP**：
  - 開網址出現「你沒有存取權」→ 存取權選錯或瀏覽器登錯帳號（多帳號最常見：網址前加 `/u/1/` 切換，或無痕重登）。
  - 網頁空白/載入中不動 → `index.html` 檔名打錯（必須叫 `index`）或 HTML 內容貼進了 `.gs` 檔。
  - 改了 code 網頁沒變 → 沒建「新版本」重新部署（頁 50 預防針先打，還是一定有人中）。
  - 新增訂單沒反應 → 看瀏覽器 console 太深了，直接對照保底碼重貼。
- **時間管理**：這環節不可壓縮（成功指標三）。若前面吃掉時間，砍的是收尾的 e2e 回顧講述長度，不是這裡。
- **收尾動作**：留 1 分鐘讓大家用手機開自己的網址互相看——這是拍照發社群的時刻。

### 收尾（15 min）

安全紅線三條（handbook 最後一節）務必唸完，特別是「自動信只寄自己、send 留給人」——這是你對企業學員的職業責任。問卷 QR 放著讓大家掃完再走。

## 4. 答案與驗收頁（只有你知道）

- **動手 4 為什麼一定寄信**：範本數據 F3＝+69.31（價漲）、F4＝−1300（庫存降），條件 `庫存增減<0 && 價格漲跌>0` 成立。E3＝13,487.86、E4＝305,200 會出現在信裡。
- **動手 5 答案**：**C002**（最後下單距今約 137 天；買的是不鏽鋼螺栓、鋼管材——**鋼的客戶**）、**C007**（約 100 天；鋁型材、鋁支架——**鋁的客戶**）。其餘 C001/C003/C004/C005/C006/C008 都在近兩個月內有單。
  - 驗收台詞：「大家的名單裡是不是都有 C002 和 C007？一個沉默一百三十幾天、一個一百天——這就是 Eddy 說的『讓沉睡的訂單開口』。」
  - 追問彩蛋（有時間再用）：「C007 是鋁的客戶——剛剛動手 4 我們才看到鋁價在漲。沉睡的鋁客戶＋上漲的鋁價，這就是下一封提案信的劇本。」
- **動手 8 週報數據合理範圍**（判斷 AI 有沒有亂編）：歷史訂單 41 筆；**銅的金額佔比最高**（銅品項單價 90–140，遠高於鋼 19–43、鋁 35–55，且大單多：39,300×2、29,400、27,800、27,200）；鋼、鋁次之。若 AI 說「鋼是主力」或編出不存在的品類，示範指出「這就是要人工檢核的原因」。
- **「最近四週金額」注意**：歷史訂單最後幾筆落在課程日前一至兩週，更早的週可能是 0——AI 週報若寫「近週下滑」是正常反映資料，不是錯。

## 5. 課堂 Q&A 預想

| # | 問題 | 建議回答 |
|---|---|---|
| 1 | 回公司能用企業帳號嗎？ | 看 IT 政策，很多企業 Workspace 鎖 Apps Script 或觸發器。先用個人帳號練熟，要上線時拿著成果去找 IT 談，成功案例比申請單有說服力。 |
| 2 | Gemini API 要錢嗎？ | AI Studio 的 key 有免費層，flash 模型免信用卡就能用，我們課堂用量遠踩不到上限。要注意的是免費層資料會被 Google 用於改善模型，所以不要送真客戶資料。 |
| 3 | 觸發器會不會半夜亂寄信？ | 只在你設定的時段跑（我們設每週一 8–9 點）。要停就到「觸發條件」把它刪掉。另外「每小時」型觸發器不保證準點，會在該時段內任意時間執行。 |
| 4 | 這跟 Day 2 的 PAD 差在哪，以後用哪個？ | PAD 強在操作「你電腦上的軟體和網頁」（抓資料），GAS 強在「雲端的 Google 全家桶」（判斷＋行動），是接力不是取代——今天的行情資料就是 PAD 抓回來的。 |
| 5 | API key 外洩會怎樣？ | 別人可以用你的額度呼叫 API，綁了付費就可能產生費用。所以放指令碼屬性、不截圖、不上傳。真外洩了回 AI Studio 刪掉重建一組就好。 |
| 6 | 可以直接自動寄給真客戶嗎？ | 技術上可以，職業上不要。系統負責「不漏、備好草稿」，按送出的判斷永遠留給人——一封語氣不對的自動信毀掉的信任，比省下的時間貴。 |
| 7 | Gmail 一天能寄幾封？ | 個人帳號約 100 個收件人/天，Workspace 更多。我們只寄自己，完全夠用。 |
| 8 | Gemini 生的程式碼安全嗎？會不會偷資料？ | 程式碼是死的，它只做你看得到的事——這正是環節一教你「看得懂讀哪格、寄給誰」的原因。貼上前掃一眼有沒有奇怪的網址或寄件對象。 |
| 9 | 試算表資料變多會不會跑很慢？ | 幾千列都沒問題。GAS 單次執行有 6 分鐘上限，等你的資料大到會超時，就是該升級工具的時候了（Day 4 見）。 |
| 10 | 我可以把今天的專案分享給同事嗎？ | Sheet 副本、程式碼、prompt 都可以分享；**API key 不行**，每人自己申請一組。 |
| 11 | 為什麼我的 Gemini 生的跟隔壁的不一樣？ | AI 每次生成都有隨機性，正常。判斷標準只有一個：跑得動、結果對。跑不動就用保底碼，不用糾結。 |
| 12 | 觸發器設好了，電腦要開著嗎？ | 不用，這就是今天的重點——GAS 住在 Google 雲端，你電腦關機、人在睡覺，它照跑。 |
